## 透過 GitHub 在另一台電腦使用

先安裝 Git 和 Python 3.10 以上，使用有此私人倉庫權限的 GitHub 帳號下載程式。

```powershell
git clone https://github.com/sdasdasd1223/customer-management-system.git
cd customer-management-system
```

將原電腦的 `.env` 私下複製到專案根目錄，再雙擊「啟動系統.bat」。首次啟動需連網安裝套件，之後開啟 `http://127.0.0.1:8000` 使用飛書登入。也可複製 `.env.example` 為 `.env`，依 `FEISHU_LOGIN.md` 填入設定。

日後在專案資料夾執行 `git pull` 取得新版，再重新啟動系統。本機的設定、資料庫和附件各自保存在該電腦。GitHub 同步程式，正式團隊資料由雲端網站保存。只需處理日常客戶業務時，可直接使用 `https://120.76.179.118/money/`。

Git 排除 `.env`、`data`、附件、搬移壓縮包、部署備份與開發快取。需要搬移本機業務資料時，請依下方「資料位置與備份」操作。

## 本機開啟

Windows 雙擊「啟動系統.bat」，看到啟動訊息後，在瀏覽器開啟 <http://127.0.0.1:8000>。使用期間保留啟動視窗；關閉視窗會停止服務，資料仍會保存。

首次使用需依 [飛書登入設定與測試](FEISHU_LOGIN.md) 建立企業自建應用，填寫根目錄 `.env` 的 App ID、App Secret、返回網址及企業識別碼。沒有設定時僅顯示登入提示，不會開放業務資料。修改設定後可雙擊「重新啟動系統.bat」。

也可在本資料夾執行：

```powershell
python -m pip install -r requirements.txt
python app.py
```

需 Python 3.10 以上。啟動腳本優先使用已安裝 Flask 的專案虛擬環境，其次使用系統 Python。首次缺少套件時才安裝。開發用啟動方式僅供本機測試，正式雲端部署使用下方容器設定。

## 第一版已確認的規則

- 使用飛書企業帳號登入，不另建密碼；限定設定企業且有應用可用權限的使用者。新使用者先等待管理員分配身分，通過後才可讀寫客戶、合同及附件；管理員可看全體資料；純業務員只看自己登記的未分配線索，以及分配給自己負責的客戶、跟進、合同、附件及統計。
- 管理員在「人員與身分」以兩個勾選項分配管理員及業務員，可同時具備兩種身分。兼具兩者按管理員權限查看全體，也可作為業務員被分配案件；兩項都不勾選則退回待分配。業務員姓名取自飛書，帳號以固定識別碼綁定，改名不會產生重複人員；不再手動新增姓名。既有手動業務員資料可在分配時明確綁定，保留原客戶及合同關聯。
- 目前林育丰、塗是淦（亦接受飛書顯示為「涂是淦」）為初始管理員；李海兵暫按一般帳號走身分分配流程。在指定企業第一次驗證姓名後固定綁定其帳號，之後不會僅因其他帳號同名就取得相同身分。若登入後改名，既有身分保留；待確認的同名帳號需由管理員處理。
- 線索保留登記人的帳號。管理員可以刪除所有未分配線索，業務員只能刪除自己登記的未分配線索；分配成客戶後所有人都不能刪除，已有合同的資料也不能刪除。舊線索沒有登記人紀錄，只允許管理員刪除。
- 正式資料從空白開始，不載入原型的示範客戶、歷史業績或業務員姓名。
- 新線索先出現在卡片，不在登記時指定業務員。分配後使用同一筆客戶資料進入案前接觸，電話、地區及描述完整保留。
- 客戶有案前接觸、報價整理、報價確認、合同簽約、簽約完畢等階段。新增任何一份合同會進入合同簽約；仍有簽約中合同就維持此階段，全部合同簽完後進入簽約完畢。已簽客戶再新增合同會回到合同簽約，既有業績仍保留。
- 每位客戶可有多份合同，不另設案件管理頁。合同各有編號、名稱、金額、負責業務員、狀態、簽約日期及附件。
- 合同只有「簽約中」「簽約完畢」兩種狀態。必須有實際保存、類型為「已簽合同」的附件，且填寫實際簽約日期，才能手動確認完成。上傳草案或報價單不會使合同完成，也不會自動計入業績。
- 附件支援 PDF、JPG、PNG、DOC、DOCX，單檔上限 20 MB。PDF 與圖片可直接預覽；Word 文件下載開啟。已簽合同至少保留一份已簽附件，要替換時先上傳新檔。
- 簽約完畢即算業績，不計算回款、稅額或拆分業績。合同可選一名負責業務員。客戶換負責人不會自動更動既有合同的業務員，合同可另外修改。
- 未分配線索不計入待簽業務。已分配但尚無合同的客戶，待簽額為預估金額；有合同後，改為簽約中合同金額合計，不再加上原預估額。已簽金額是所有已簽合同合計。
- 年度、月度實際業績以每份合同的實際簽約日期歸屬；可補登往年資料，不能填未來日期。新增跟進紀錄不會改變簽約日期。修改已簽合同的金額或日期會重新計算統計，操作保留紀錄。
- 年度指標按年保存。月度計畫＝年度指標÷12；時間進度＝（已過完整月份＋本月已過天數÷本月天數）÷12；應完成額＝年度指標×時間進度；完成率＝年度已簽÷年度指標。往年時間進度為100%，未來為0%。未設定指標時，完成率顯示「未設定」。
- 「總覽」年度數字依選定的統計年度；「業務池」與業務員已簽金額顯示所有年度，畫面有標示。所有月份都由真實合同統計，無合同的月份為0。
- 保留原有視覺風格，移除模擬飛書線索、虛構回款及未實作的資料介面導覽。本版新增飛書登入，線索機器人及財務外部資料未串接。

金額畫面單位為萬元，最多六位小數；資料庫以人民幣「分」保存整數，避免加總誤差。圖表和百分比為顯示值。

## 資料位置與備份

預設資料位置為專案中的 `data`：

```text
data/
  database.sqlite3
  uploads/
```

可透過 `DATA_DIR` 環境變數指定固定資料夾。資料庫啟用外鍵、寫入交易及並行等待；多人分配同一線索時僅一次成功。客戶與合同修改有版本檢查，舊畫面不會直接覆蓋別人剛改的資料。

側邊欄「下載完整備份」會產生 ZIP，包含可還原的資料庫快照、快照引用的全部附件及備份清單。也可用命令建立備份，適合日後設定伺服器排程：

```powershell
python backup.py --output backups/簽單台備份-20261028.zip
```

備份檔應另外保存到不同裝置或雲端空間。系統不會自動替使用者建立異地備份。附件從畫面刪除後，原檔暫留磁碟，避免並行備份引用到不存在的檔案；下載的備份只帶目前被引用的附件。

資料庫也保存本系統使用者及登入狀態，備份檔同樣視為機密資料。飛書 App Secret 在 `.env`／伺服器環境變數中，飛書 access_token 不落地，備份 ZIP 不含這些憑證；還原到新主機時需另外配置 `.env`。

還原時先停止系統，另存目前 `data`，再把備份內的 `database.sqlite3` 和 `uploads` 解壓至新的資料目錄，將 `DATA_DIR` 指向該目錄後啟動。請勿在程式仍運作時直接覆蓋資料庫檔案。測試已驗證備份可還原並保留合同與附件。

## 雲端部署準備

提供 Dockerfile 與 compose.yaml，使用 Gunicorn 執行後端，使用永久資料卷保存資料。於已安裝 Docker 的 Linux 主機執行：

```sh
docker compose up -d --build
```

容器預設只把服務綁定主機的 `127.0.0.1:8000`，由伺服器的反向代理提供外部連線及 HTTPS。`deploy/nginx.conf.example` 提供代理設定範例，需換上實際網域、憑證及允許連線的 IP。compose 已設定 `TRUST_PROXY=1` 接受本機代理轉送的 HTTPS 資訊；直接提供服務時不要啟用此設定。更新程式可重新建置容器，資料卷保留；不要執行會刪除資料卷的 `docker compose down -v`。

本版已加入飛書登入與企業檢查，業務介面、資料、附件、備份均檢查登入狀態；寫入與登出亦需頁面驗證。正式上線需設定 HTTPS、飛書回調網址與可用人員範圍。反向代理範例仍預設限制來源，是否調整由實際部署環境決定。

2026-10-29 已部署至 `https://120.76.179.118/money/`，並以真實飛書帳號驗證登入。本次使用主機上的獨立 Python 環境與系統服務，沒有使用 Docker。目錄、原有網站、部署檢查、資料備份及撤回方式詳見 [部署紀錄](deploy/DEPLOYMENT.md)。定期異地備份尚未設定。

若與其他網站共用主機，並選擇使用 `/money`，設定 `APP_BASE_PATH=/money`，以及未被占用的 `SIGNING_HOST_PORT`（例如 `18080`，須先確認）。飛書返回網址必須改為 `https://實際主機或網域/money/auth/feishu/callback`，並同步登記到飛書後台。登入、靜態資源、資料請求、附件及備份都會加上此子路徑；登入 Cookie 也只作用於 `/money`。本機預設留空仍使用原來的根路徑。

`deploy/nginx.money.locations.example` 是加入既有 HTTPS 網站的子路徑範例。部署前需先盤點原有網站設定、確認路徑與連接埠沒有占用，再備份並檢查設定。不要以 `deploy/nginx.conf.example` 取代共用主機的原有網站設定。範例關閉 `/money` 的 Nginx 存取紀錄，以免授權碼寫入含完整查詢字串的日誌；Gunicorn 仍保留不含查詢字串的請求紀錄。

### 流失池與重新分配

客戶詳情可選「客戶流失／移入流失池」，必填原因。管理員可操作全部客戶。業務員只可操作目前自己負責的客戶。已有任何簽約完畢合同時，禁止將整個客戶移入流失池。

移入後解除負責人，清除本輪分配時間與下次跟進。管理員可在線索池的「流失池」分頁查閱及重新分配。既有流失客戶也顯示在流失池。線索池的待分配筆數和預估金額只計一般線索。重新分配後，客戶回到案前接觸，新負責人可查閱過去跟進、流失原因及原負責人紀錄。

未簽合同及附件保留為「合同流失」，只能查閱、下載，不可完成簽約或修改、刪除附件；不計入待簽金額或業績。重新分配後若再次合作，建立新合同；舊合同不自動恢復。流失退回的客戶不可當一般新線索刪除。
